go mod tidy:

Ele analisa os imports do seu projeto e ajusta as dependências do módulo.

Por exemplo, você começa a usar:

import "github.com/gin-gonic/gin"

e executa:

go mod tidy

O Go garante que as dependências necessárias estejam registradas.
Também remove dependências que não são mais necessárias.

Pense nele como uma ferramenta de limpeza/sincronização das dependências.

Quando você inicializa uma struct com campos normais (valores), Go atribui o valor padrão de cada tipo. Quando você usa ponteiros, o valor padrão de qualquer ponteiro em Go é sempre nil.


type EstruturaValor struct {
	Ativo  bool
	Nome   string
	Idade  int
}

type EstruturaPonteiro struct {
	Ativo  *bool
	Nome   *string
	Idade  *int
}

func main() {
	v := EstruturaValor{}
	fmt.Printf("Valor -> Ativo: %t, Nome: %q, Idade: %d\n", v.Ativo, v.Nome, v.Idade)
	// Saída: Ativo: false, Nome: "", Idade: 0

	p := EstruturaPonteiro{}
	fmt.Printf("Ponteiro -> Ativo: %v, Nome: %v, Idade: %v\n", p.Ativo, p.Nome, p.Idade)
	// Saída: Ativo: <nil>, Nome: <nil>, Idade: <nil>
}

Dica para ponteiros -> Precisa alterar dados? Entao ponteiro. Quer ler dados? Então nao use ponteiro. Nao usando ponteiro vc passa a copia e depois 
da execução ele perde todos os dados alterados.

Interface -> Criei o PaymentProcessor, qualquer struct que tenha um metodo Pay(amount float64) error exatamente assim ira implementar a interface
PaymentProcessor.

repare que embaixo fiz processPayment -> ela diz que eu posso passar um metodo de pagamento e a quantidade não preciso especificamente ser de um tipo.
isso implementa PaymentProcessor? → então consigo chamar Pay()

Mas se eu quiser posso fazer 

PixPayment{}.Pay(100) que ai nao preciso chamar a funcao processPayment que espera alguem que implemente a função Pay.

Posso chamar PixPayment{}.Pay(100) diretamente, porque estou trabalhando com o tipo concreto PixPayment. Já processPayment recebe um PaymentProcessor, então ele aceita qualquer tipo que implemente Pay(amount float64) error.


type PaymentProcessor interface {
	Pay(amount float64) error
}

type PixPayment struct{}
type CreditCardPayment struct{}

func (p PixPayment) Pay(amount float64) error {
	fmt.Println("Processing PIX payment:", amount)
	return nil
}

func (c CreditCardPayment) Pay(amount float64) error {
	fmt.Println("Processing Credit Card payment:", amount)
	return nil
}

func processPayment(payment PaymentProcessor, amount float64) error {
	return payment.Pay(amount)
}

processPayment(PixPayment{}, 100)
processPayment(CreditCardPayment{}, 200)

//SUPONHA QUE TENHA O METODO Show()
type PaymentProcessor interface {
	Pay(amount float64) error
	Show()
}

E você faz:
type PixPayment struct{}

func (p PixPayment) Pay(amount float64) error {
	fmt.Println("PIX:", amount)
	return nil
}

Nesse momento, PixPayment não implementa PaymentProcessor, porque falta: Show()

Se tentar executar: processPayment(PixPayment{}, 100) o Go vai reclamar em compilação, porque PixPayment não satisfaz a interface.

Você teria que fazer:

func (p PixPayment) Show() {
	fmt.Println("Showing PIX payment")
}
